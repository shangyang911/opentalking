    会员、额度与内测人工收款¶

    当前版本提供有限试用、VIP 套餐、加量包、管理员赠送与人工核实订单。用户从工作台顶部或驱动方式下方的“会员与额度”查看权益和创建订单；管理员从 /admin 的运营概览管理同一套账本。

    个人中心 /account 统一展示会员、时长、额度来源与有效期、订单和最近 100 次任务结算。月度 VIP 固定 30 天，新增或编辑 VIP 套餐时服务端校验此周期；历史订单快照和已有权益保持原值。管理员配置实际售价、对话/视频时长和单次上限后上架。续费延长有效期并发放新增时长，不自动扣款。账户展示可用时长而非人民币储值余额。

    QuickTalk 可用时长与对话总时长分别展示：免费轻量额度计入总时长，但不能代替 QuickTalk 体验或付费/赠送时长。当前任务已预留的部分单独说明。GET /billing/me 增加 grants 字段；GET /billing/activity 返回本人最近 100 次任务的预留秒数、实际使用秒数、状态和体验标识，不返回其他账号或内部额度分配。

    月度 VIP 不限总时长¶

    当前月度 VIP 为 ¥100／30 天。管理员勾选“有效期内对话、视频不限总使用时长”（套餐字段 unlimited=true）后，VIP 有效期内可持续使用 QuickTalk、轻量对话、视频、试听与专属声音创建，不扣减对话或视频总余额。有限试用、赠送及历史有限额度订单保留原规则；套餐调整只影响之后的订单。

    不限总时长不等于单个任务无限运行：单次对话仍受套餐上限控制，单次视频仍受部署的 OPENTALKING_BILLING_VIDEO_MAX_SECONDS 限制，同时保留并发、输入长度与调用频率限制。任务不能超过所用 VIP 的到期时间，结束后可在有效期内继续发起任务。服务用量和成本仍照常记录。

    GET /billing/me 返回 unlimited 和 unlimited_until，各项权益及使用记录也标记是否不限总时长。个人中心与会员窗口优先展示会员状态、VIP 到期时间和剩余有效期，不足一天时显示“不足 1 天”；未开通时不显示虚构的到期日期。不限总时长 VIP 不再显示分钟余额卡片，有限套餐、试用与赠送额度仍单独展示。后端依据订单权益实际校验，不使用巨额分钟数伪装无限额度。到期、撤销或关闭演示模式会撤销对应访问权限。

    演示用户与管理员 VIP 联动¶

    在 .env 设置 OPENTALKING_BILLING_DEMO_ENABLED=true，保持认证和会员控制启用，重新构建前端并重启 API、worker。该开关默认关闭，不需要支付平台密钥。

    1. 管理员在 /admin 上架 VIP 套餐，设置演示售价、对话/视频时长及单次上限。VIP 有效期为 30 天。
    2. 在另一标签页登录普通用户，打开“会员与额度”或个人中心，创建订单并点击“模拟付款”。此时仍未开通 VIP。
    3. 返回管理员标签页，订单列表会自动刷新，点击“确认演示开通”。无需真实付款、收款流水号或切换登录账号。
    4. 用户端每三秒检查待确认演示订单，确认后自动显示 VIP 和新增时长；对话、视频、额度扣减仍走真实后端流程。
    5. 管理员可点击“撤销演示权益”恢复演示前的付费权益，再下单重演。存在进行中的任务时需先结束任务。

    演示订单永久携带演示标记，不计入真实收款、退款和付费用户统计，也不能通过真实确认/退款接口处理。关闭开关并重启 API、worker 后，演示授予的 VIP 与时长不再可用，原有正式订单和权益保留。支付是模拟的，实际调用 LLM、语音或推理服务仍会发生。

    演示接口为 POST /billing/orders/{order_id}/demo-pay、POST /admin/billing/orders/{order_id}/demo-confirm 和 POST /admin/billing/orders/{order_id}/demo-revoke；默认关闭，仍严格检查用户归属与管理员角色。

    正式会员配置¶

    保持账号认证开启，OPENTALKING_BILLING_ENABLED=true 默认启用会员控制。MySQL 应用账号需要创建新增 billing_* 表的权限；使用增量建表，不删除账号或作品。若需不受额度限制的私有部署，可以明确设为 false，前端通过 /auth/status 的 billing_enabled 同步隐藏入口与检查。

    更新后应重新构建前端并重启 API 与 worker，三者使用同一版本；旧 worker 不具备本版的额度计时与到期关闭逻辑。已经启动的旧运行副本不会因源码修改自动升级。

    套餐默认未上架、价格为零。管理员先测量成本，在“会员、订单与服务成本”设置套餐名称、售价、对话秒数、视频秒数、单次对话上限与有效天数，再勾选上架。没有预设商业价格或无限套餐。套餐变更只影响之后创建的订单，待确认订单保留原价格和权益快照。

    内测可先选择用户，填写赠送分钟数、有效天数和原因；赠送不计入营收，也不表示开通付费 VIP。礼赠对话额度可用于 QuickTalk。加量包要求已有有效 VIP，到期不晚于当前 VIP。购买 VIP 一次性发放套餐额度；再次购买会延长有效期并增加额度，没有自动续扣或按月自动重置。

    根目录私有 .env 可设置 OPENTALKING_BILLING_PAYMENT_INSTRUCTIONS，向用户展示联系管理员和核实付款的说明。无需填写支付平台密钥；本版没有微信/支付宝商户支付接口，也不会根据付款截图自动到账。

    订单与收入¶

    1. 用户选择已上架套餐，后端按套餐快照创建待确认订单。重复请求编号返回同一订单，账号最多保留五笔待确认订单，可自行取消。
    2. 用户按管理员说明线下付款，备注订单号。管理员在实际收款渠道核实付款人、金额和订单。
    3. 管理员点击“核实到账”，填写唯一收款流水号并确认已核实。订单状态变为已到账和发放权益在同一数据库事务完成；重复确认不会重复增加额度，流水号不能用于其他订单。
    4. 用户刷新会员窗口查看余额；用户订单与后台金额读取相同记录。赠送、待确认/取消订单和消耗额度都不计收款。
    5. 若已在线下完成全额退款，管理员填写唯一退款流水号登记。它不会主动转账，只把实际退款计入账本并撤销订单剩余权益。用户存在进行中的任务时不能登记退款。撤销较早续费订单会重新计算之后订单的有效期；加量包不会比重算后的 VIP 更晚到期。

    后台分别统计确认到账、已登记退款、净收款、付费用户及已知服务成本。净收款是到账减退款；它不等于利润。成本缺失条数会单独显示，服务器、带宽和税费不包含在估算内。

    试用与扣减规则¶

    • 每个账号初始有 180 秒轻量对话、两次 QuickTalk 体验，每次最多 60 秒。由 BILLING_FREE_SECONDS、BILLING_TRIAL_COUNT、BILLING_TRIAL_SECONDS 配置；更改默认值不重置已领取账号。
    • 切换驱动不扣试用。真正创建会话前在 MySQL 中原子预留额度，账号同一时间仅允许一个计费任务。失败初始化退回额度与试用次数；成功开始后提前结束不退回“次数”，未用的普通时长会退回。
    • 对话从 /sessions/{id}/start 成功开始按连接墙钟时长计费，包括连接后等待和静音，向上取整到秒。初始化等待不计时，但预留最多保留十分钟；初始化最长等待两分钟。达到本次上限前十秒提示，到期后端关闭会话，前端结束录制并沿用自动保存流程。
    • 关闭网页或进程异常时，预留仍保存在 MySQL。未开始任务过期会退回；已开始但未能正常结算的任务按本次已预留上限结算。它不会因为刷新恢复额度。
    • 视频按实际成片音频时长扣秒，失败/停止退回视频余额，但发生过的服务调用仍保留成本记录。单次默认最多 60 秒，实际音频和双人分段总长在推理前校验，不采信客户端声称的时长。单个任务最长十分钟，且不超过所用权益有效期；每小时最多十次发起。
    • 试听同样可能调用付费服务：预留最多 15 秒对话余额，按实际合成音频扣减。专属声音需有效 VIP 或赠送权益，成功创建消耗 60 秒对话余额，每天最多三次。两类操作不能与当前任务并发。
    • 输入默认最多 1000 字符，LLM 上下文最多 12000 字符、单次回复最多 512 Token；输入请求间隔至少两秒。语音/上传音频受剩余会话时长限制。轻量驱动也受额度约束。

    用量与成本¶

    用量记录按账号和任务关联，只存服务类别、模型、计量数字与时间，不存对话内容、录音或密钥。记录 LLM 输入/输出 Token、TTS 文本字符与生成音频秒数、STT 音频秒数以及渲染时长。实时渲染按连接时长估算，视频按音频时长估算，并非 GPU 实测计算时间。

    OPENTALKING_BILLING_COST_RATES 是 JSON 对象，键和对应计价字段为：

    • llm:<模型 ID>：input_per_million、output_per_million，单位元/百万 Token。
    • tts:<服务>:<模型>：per_million_chars，单位元/百万字符；按音频计价时用 per_minute。未配置显式模型的服务键为 tts:<服务>；以后台记录的实际模型键为准。
    • stt:<服务>、render:<模型>：per_minute，单位元/分钟。

    费率必须是非负有限数，允许明确配置零表示已知免费服务。默认空对象表示未配置，不能把它视作零成本。成本按调用时配置落账，不随后来修改费率重算历史；模型缓存价、阶梯价或服务特殊计价需依据合同另行核对，不以通用估算替代服务商账单。

    LLM 开启 stream_options.include_usage，读取最后一个用量分片。服务未返回该分片或响应被中断时会保留“未知用量”，不猜测 Token。兼容服务需要支持流式用量和 max_tokens；不支持时应更换配置或适配服务。参见 OpenAI 流式响应文档。

    接口与验证¶

    用户接口：GET /billing/me、GET /billing/plans、GET/POST /billing/orders、POST /billing/orders/{id}/cancel、GET /billing/usage。用户列表订单支持 before=<created_at> 查询更早记录，每页最多一百条。

    管理员接口：GET /admin/billing、PUT /admin/billing/plans/{vip|pack}、POST /admin/billing/orders/{id}/confirm、POST /admin/billing/orders/{id}/refund、POST /admin/billing/gifts。到账/退款请求体为 receipt；创建订单和赠送需要唯一 request_id。管理员会话与用户会话仍独立。

    运行 pytest backend/tests/api/test_billing.py backend/tests/unit/test_metering.py 验证额度持久化、并发、订单隔离、幂等、退款、过期和计量；MySQL 使用与认证测试一致的 _test 数据库和随机前缀表，绝不在业务库测试。测试不会调用真实短信、模型或收款服务。
