# 知识库与长期记忆

从工作台顶部进入「知识与记忆」，页面分为「我的资料」和「关于我」。资料与记忆按登录账号隔离。

## 文档问答

1. 直接点击「添加资料」或拖入一份 TXT、Markdown、PDF、PPTX，单份最多 20 MB。首次上传自动创建「我的资料」分组并选中，不需要先新建。之后上传到当前查看的分组；资料多时可展开「新建分组」进行整理。
2. 上传后显示「正在阅读资料」；原文可检索时显示「可以提问」。深入理解未完成时仍能按原文查找内容，处理失败则可「重新尝试」。
3. 用「试问一句」输入问题，查看从资料中找到的真实原文依据；这里不额外生成完整回答，返回聊天可以继续问。PDF 依赖现有解析工具，扫描件可能需要文字识别，不能保证所有页面均可识别。
4. 勾选聊天时要参考的分组。聊天入口显示本次实际启用的资料组数和个人记忆状态；更改设置后，会单独提示「设置已保存，重新连接后生效」。点击「重新连接并应用」会结束旧会话再建立新连接；录制、保存或其他任务进行中时需先完成这些操作。设置按账号保存在当前浏览器，刷新后可恢复；不同浏览器不会自动同步。
5. 回复气泡中的「检索参考资料」列出本轮检索返回的文件名，供核对；它不是逐句引用证明。没有找到资料或检索超时时，模型会收到明确说明无法确认的约束。

完整语义/图谱检索沿用 `OPENTALKING_AGENT_LIGHTRAG_*` 配置；现有对话 LLM 负责组织口语回答。未配置完整索引服务时，基础关键词检索仍可使用，其效果不等价于语义检索。

## 明确记忆

在「关于我」开启「让数字人记住我」。用「怎么称呼我」「饮食喜好」「聊天方式」示例填写并修改内容，再点击「保存这条记忆」；点击示例本身不会保存。连接后也可说「请记住：我喜欢简短回答」，系统会在本轮回答结束后异步保存。普通聊天不会自动抽取长期记忆，否定或引用的“记住”不作为保存请求。

可直接添加、编辑和删除记忆。关闭开关后，新会话不读取也不写入长期记忆，已有条目保留。个人记忆属于登录账号，同一账号更换数字人形象、音色或重新开始会话，仍使用同一份个人记忆；其他账号无法访问。之前按数字人保存的条目也会在「我的个人记忆」中显示，不需要重新添加。删除长期记忆不会清除当前会话历史中的原话。

例如，添加「叫我小林，我喜欢清淡的食物，不吃香菜，聊天时希望语气轻松」。下次启用记忆后，可以问「推荐一道适合我的晚餐」，数字人可以参考你的饮食喜好。输入框中直接填写个人事实即可；聊天中保存仍需明确说「请记住……」。

当前版本使用统一的显式记忆入口，公开会话不启用 Mem0 自动提取。历史 Mem0/角色包数据不会自动迁移；自动摘要和自动矛盾合并留待后续版本。

## API

- `GET/POST /knowledge/bases`：列出或新建本账号知识库。
- `DELETE /knowledge/bases/{kb_id}`：删除知识库及其文档。
- `GET/POST /knowledge/bases/{kb_id}/documents`：列出文档或以 `file` 字段上传；上传返回 202，随后后台索引。
- `DELETE /knowledge/bases/{kb_id}/documents/{doc_id}`：删除文档。
- `POST /knowledge/bases/{kb_id}/documents/{doc_id}/retry`：重试索引。
- `POST /knowledge/bases/{kb_id}/query`：以 `query` 字段预览检索结果。
- `GET /knowledge/memories`：查看本账号的个人记忆（最多 100 条）。
- `POST /knowledge/memories`、`PUT /knowledge/memories/{id}`：使用 `content` 添加或修改，无需数字人 ID。
- `DELETE /knowledge/memories/{id}`：删除一条个人记忆。旧请求中的 `avatar_id` 仍被兼容，但不再用于分隔个人记忆。

创建会话时传 `memory_mode: "explicit"`、`memory_enabled`、`knowledge_enabled` 和 `knowledge_base_ids`。账号由服务端登录身份决定；指定其他账号的知识库返回 404。关闭认证的本地开发模式使用 `local` 作用域，不提供多用户访问隔离。
